# 1주차 · PRD + 단계별 자동화 설계안 | 유이 (B팀)

마감: **11/4(수) 저녁 9시** · 1차 싱크 전

> 출발점: 이미 돌리고 있는 「약사 상담 콘텐츠 파이프라인」(정하기 → 모으기 → 만들기 → 거르기 → 넘기기 → 배우기)이 있어요.
> 이번 유닛에서는 이걸 **진행 현황판** 수준에서, **유이 전담 AI 팀 + 감독관이 굴리고 스스로 배우는 종합 대시보드**로 키워요.
> 참고: 스폰지클럽 워크플로우 스타트킷 · 에밀리의 ROY 키트(BYEM)에서 시작한 원칙 — 숫자는 계산기가 · 판단마다 규칙 번호 · 보기만 하고 누르지 않기 · 사람은 승인 · 보류 · 반대만.

## 1. 한 줄 요약
약사 대상 카카오톡 · 문자 콘텐츠의 **기획 · 조사 · 제작 · 리뷰 · 성과 분석 · 러닝 · 다음 전략**을, 역할이 나뉜 AI 팀원들이 맡고 **감독관이 빠짐없이 챙겨서**, 관리자(유이)에게는 「승인 · 보류 · 반대」할 것만 한 화면에 올려 주는 시스템.

## 2. 지금 하는 방식
- 순서: 주제 정하기 → 근거 · 자료 찾기 → 원고 · 카드 4장 + 문자 1장 → 디자인(외부 툴 + 캔바) → 디자인 검수 → 의학 · 규제 리뷰(MA · RA) → 반영 → 발송 → (성과는 따로 확인, 다음 편에 잘 안 이어짐)
- 주기와 걸리는 시간: 한 편이 여러 부서를 사람이 이어 주며 몇 주. 성과를 보고 다음 편에 반영하는 고리가 약함
- 지금 만들어 둔 것: 단계별 스킬(전체 흐름 · 리뷰 · 디자인 검수) · 상태 파일 하나 → **진행 현황판** · 관리 시트 연동
- 아쉬운 점: 내가 알림판을 보고 다음 일을 직접 시켜야 해요. 디자인은 밖(캔바)에서, 성과는 또 다른 곳에서 봐요. 매번 새로 생성하느라 토큰을 많이 써요.

## 4. 자동화 흐름 — 「유이 전담 팀」

```
                      ┌──────────── 관리자(유이) : 승인 · 보류 · 반대 + 이유 ────────────┐
                      │                                                               │
                [감독관] 매일 상태를 훑고 → 다음에 누가 뭘 할지 고르고 → 빠진 곳 · 밀린 곳 경고
                      │
 기획자 ─▶ 조사원 ─▶ 제작자 ─▶ 리뷰어 ─▶ (사람 심의 · 발송) ─▶ 분석가 ─▶ 러닝 담당 ─▶ 전략가
   ▲                                                                              │
   └──────────────── 판단 규칙 · 틀 · 금지 표현이 업데이트되어 다음 편에 쓰임 ◀────────┘
```

| 팀원 | 맡는 일 | 전문성이 쌓이는 곳 (내 파일) | 토큰 |
|---|---|---|---|
| **감독관** | 모든 건의 단계 · 기한 · 빠진 칸을 점검, 다음 일 배정, 관리자 승인함 정리 | 점검표 · 기한 규칙 | 적음 (대부분 스크립트) |
| 기획자 | 다음 편 주제 고르기 (자주 묻는데 아직 없는 질문 · 성과 좋았던 유형) | 정하기 규칙 P1~ | 중간 |
| 조사원 | 근거 · 질문 모으기, 출처 붙이기 | 근거 은행 · 출처 목록 | 중간 (웹은 Aside) |
| 제작자 | **틀에 원고만 채워** 카드 4장 + 문자 생성, 대시보드 안에서 바로 편집 | 카드 틀 · 문장 패턴 · 좋은 예 | **적음** (틀 채우기) |
| 리뷰어 | 의료기기 광고 관문(R1~) 판정, 지난 지적 재대조 | 관문 · 리뷰 사례(RC) | 중간 |
| 분석가 | 발송 성과를 **계산기로** 집계 → 판단 규칙으로 유지 · 수정 · 중단 판정 | 판단 규칙 rs-1~ · 목표치 | **0** (계산) + 적음 (설명) |
| 러닝 담당 | 관리자 결정 · 리뷰 지적 · 성과를 규칙 · 틀에 반영하자고 **제안** | 학습 로그 · 규칙 변경 이력 | 적음 |
| 전략가 | 월 1회 쌓인 성과로 다음 달 시리즈 방향 3안 | 전략 메모 | 많음 (월 1회만) |

### 토큰을 아끼는 설계 — 「틀은 시스템이, 판단만 AI가」
1. **0토큰 영역 (코드가 함)**: 성과 계산 · 금지 표현 검사 · 필수 표기 검사 · 카드 렌더 · 상태 점검 · 기한 경고
2. **조금 쓰는 영역**: 정해진 틀의 빈칸(제목 · 본문 · 버튼)만 채우기, 판정 근거 한 줄
3. **많이 쓰는 영역**: 새 주제 기획 · 월간 전략 — 횟수를 정해 둠
4. 러닝 결과는 **파일(규칙 · 틀 · 좋은 예)** 로 남겨서, 다음 편은 다시 생각하지 않고 꺼내 씀 → 편이 쌓일수록 토큰이 줄어듦

### 채널 · 청중 구조 — 「하나로 운영, 보기는 청중별로」
- **하나의 콘텐츠(메시지) → 청중별 원고 2벌 → 채널별 베리에이션**
  - 약사 · HCP 라인: 카카오톡 · 문자(LMS) · HCP 이메일 · 링크드인(실험)
  - 대중 라인: 인스타(오가닉) · Meta 광고 (나중에 유튜브)
- 시스템 · 콘텐츠 번호 · 감독관 · 러닝은 **하나**: 약사에게 통한 메시지가 대중 기획의 재료가 되고, 감독관은 전체를 한 번에 봐야 빠짐이 없어요
- 라인별로 **나누는 것**: 리뷰 규칙집(약사용 / 대중 광고 — 대중 대상 의료기기 광고는 사전심의) · 목표치 · 제작자 · 데이터 접근 권한
- 모든 채널을 같은 줄(분모 → 반응 → 행동 → 전환)로 맞춰서, 새 채널은 **열 이름 맞추기(어댑터)만** 추가하면 붙어요
- 스마트스토어 · 쿠팡 같은 이커머스는 콘텐츠 베리에이션이 아니라 **결과(매출) 데이터**로 대중 라인 뒤에 붙여요 → 3주 범위 밖
- B안(Meta 광고 연습)은 대중 라인의 Meta 광고 **시뮬레이션 데이터**로 같이 커버해요

## 5. 사람이 확인할 곳
- **관리자 승인함** (대시보드 한 탭): 주제 확정 · 원고 확정 · 규칙 변경 · 다음 달 전략 → 승인 · 보류 · 반대 + 이유 (이유가 러닝 재료)
- **MA · RA 심의 · 심의필 · 발송 버튼은 사람만.** AI는 「승인 대기」까지만
- 성과 판정은 제안일 뿐 — 중단 · 재발송은 사람이 결정
- 목표치(오픈율 · 클릭률 · 문의 수 기준)는 관리자가 정함. 없으면 「높다 · 낮다」를 말하지 않음

## 7. 단계별 자동화 설계안

| 단계 | 입력 | 하는 일 | 출력 | 도구 · 연결 | 대시보드 탭 이름 |
|---|---|---|---|---|---|
| 1 | 상태 파일 · 관리 시트 | 감독관이 모든 건의 단계 · 기한 · 빠진 칸 점검, 다음 일 배정 | 오늘 할 일 · 승인함 | Node 스크립트 + Claude Code | 오늘 |
| 2 | 질문 목록 · 지난 성과 · 정하기 규칙 | 다음 편 후보 고르기 | 후보 3개 + 이유 | Claude Code · Aside | 기획 |
| 3 | 확정 주제 · 근거 · 카드 틀 | 틀 빈칸 채우기 → 렌더 → 화면 편집 | 카드 4장 + 문자 PNG | 렌더 스크립트 · 브라우저 편집 | 제작 스튜디오 |
| 4 | 원고 · 관문 · 리뷰 사례 | 관문 판정 · 지난 지적 재대조 | 차단 · 권고 표 | `/mlr-review` 스킬 | 리뷰 |
| 5 | 발송 성과 CSV · 목표 · 판단 규칙 | **계산기로 집계 → 규칙으로 판정** | 성과표 + 판정 + 다음 액션 | Python/Node 계산기 + Claude Code | 성과 진단 |
| 6 | 관리자 결정 · 리뷰 지적 · 판정 결과 | 규칙 · 틀 업데이트 제안 → 승인되면 반영 | 규칙 변경 이력 | Claude Code | 러닝 |

성과 진단 판단 규칙 (B팀 「끌 것 / 올릴 것」을 모든 채널로)
- r-1 한 번으로 판단하지 않아요. 1회 미달은 「지켜보기」, 분모가 적으면 「아직 모름」
- r-2 같은 채널 · 같은 청중끼리만 비교해요
- r-3 반응은 되는데 행동이 없으면 → 첫 장 · 버튼 · 랜딩부터 (주제를 버리는 건 그다음)
- r-4 반응이 낮으면 → 제목 · 미리보기 · 보낸 시간부터
- r-5 2회 연속 반응도 행동도 미달 → 중단 후보 (결정은 관리자)
- r-6 목표는 관리자가 정해요
- r-7 (광고) 빈도 3 이상 + 클릭률 20% 넘게 하락 → 소재 피로, 새 소재
- r-8 (광고) 지출 증가 ≠ 예산 변경
- r-9 한 콘텐츠가 두 채널 이상에서 같이 부진 → 채널 각색이 아니라 메시지 문제 → 기획자

**11/11에 완성할 첫 번째 탭:**
- 탭 이름: **성과 진단**
- 11/11에 실제로 되어야 하는 것: 6개 채널 성과 CSV(샘플 · Meta 광고는 시뮬레이션)를 넣고 실행하면 → 계산기가 채널별 반응률 · 행동률 · 구매율 · CPA를 계산 → 판단 규칙 r-1~9로 판정 + 근거 숫자 + 규칙 번호 → 제안이 관리자 승인함에 올라오고, 승인 · 보류 · 반대 + 이유가 저장됨. 열 이름이 다르거나 비었으면 화면에 오류로 알려 줌. (프로토타입에서 이미 동작 확인)

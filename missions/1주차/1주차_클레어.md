# 1주차 · PRD + 단계별 자동화 설계안 | 클레어 (F팀)

마감: **11/4(수) 저녁 9시** · 1차 싱크 전

## 1. 한 줄 요약
돌잔치 플랫폼 모멘트리의 검색 · 카페 · 스레드 글감 신호와 플랫폼 · 카페의 기존 글을 받아서, 인스타 캐러셀과 스레드 글 초안을 만들어, 최종 검수하고 발행하는 나에게 주고, 그 성과로 다음 글감 · 후킹 문구 · 소재 전략을 제안받아요.

```
검색 · 카페 · 스레드에서 글감 찾기 → 플랫폼 가이드 글 쓰기 → 인스타 캐러셀 · 스레드 글로 바꾸기 → 성과 보기 → 다음 전략 제안
                                     카페 기존 글도 재료로 ↗
```

## 2. 지금 하는 방식
지금은 채널마다 따로 만들고, 앞에 쓴 글이 다음 채널로 이어지지 않아요.

- 순서
  - **가이드 글:** SEO 작업으로 따로 써요. Aside로 우리 웹페이지의 최신 업체 정보를 읽어 업체 대장을 만들고, 그걸 바탕으로 글을 써요. 글감은 글 유형 메뉴와 이미 있는 글 목록을 보고 정해서, 검색 · 반응 데이터를 근거로 고르지는 않아요.
  - **캐러셀:** 캔바에서 ① 사진 찾기 → ② 내용 기획 → ③ 글 넣기 순서로 만들어요. 가이드 글을 재료로 쓰지는 않아요. 만드는 부담이 커서 지금은 업체 프로모션 위주로만 운영해요.
  - **스레드:** 직접 글을 쓰기보다 캐러셀을 올릴 때 같이 올리거나, 돌상 · 돌잔치 · 스냅을 찾는 사람들의 글에 댓글을 달아 플랫폼을 알려요. 댓글 초안은 이미 스킬로 만들고 올리는 건 내가 해요. 내가 답글 단 글의 질문은 월 1회 글감 노트에 모아요. 그런 글이 적은 시즌에는 올릴 게 애매해요.
  - **카페:** 글을 거의 안 써요. 카페 글을 플랫폼으로 옮기려다, 내용이 겹치면 양쪽 노출에 안 좋을 수 있다고 해서 멈췄어요.
- 주기와 걸리는 시간: 캐러셀 1개에 전체 3시간쯤. 가이드 글은 워크플로우를 만들어 한 편에 약 6시간 → 약 2시간으로 줄었어요.
- 문제: 글 쓰는 것 자체가 부담이라 채널마다 새로 만들수록 발행이 끊겨요. 좋은 글이 있어도 한 채널에서 끝나고, 검색어 · 카페 · 스레드 신호가 곳곳에 쌓여 있어도 한곳에서 묶어 글감으로 고르지 못해요.

## 4. 자동화 흐름
1. **글감 찾기:** 이미 모이는 네 가지 신호를 주제로 묶어요. 얼마나 찾나(키워드 검색량 · 검색어), 뭘 궁금해하나(카페 글 · 스레드 글감 노트), 어디가 비었나(AI 답변에 우리 글이 안 나오는 질문), 뭐가 먹혔나(지난 콘텐츠 성과). 모멘트리가 답할 수 있는 주제를 앞에 놓아요.
2. **겹침 확인:** 주제마다 이미 쓴 글이 있는지 사이트맵 · 콘텐츠 원장과 자동으로 대조해요. 없으면 「새 글감」, 플랫폼에 있으면 「기존 글 활용」, 카페에만 있으면 「플랫폼용으로 새로 쓰기」로 표시해요.
3. **글 쓰기:** 새 글감은 내가 고른 뒤 기존 가이드 글 워크플로우로 넘겨요. 돌잔치 준비 가이드나 테마별 업체 소개 글이 여기 해당돼요.
4. **재료 정리:** 가이드 글 주소나 카페 글을 넣으면 본문의 숫자 · 조건을 뽑아 업체 대장과 대조해요. 없거나 다른 값은 「확인 필요」로 표시해요.
5. **채널 변환:** 내 후킹 문구 모음을 참고해 표지 문구 3안을 만들고, 내가 하나 고르면 캐러셀 9장 원고 · 캡션을 만들어요. 긴 글은 스레드에 공유할 짧은 글로도 바꿔요.
6. **이미지 만들기:** 원고에 나온 업체의 사진을 공개 데이터에서 자동으로 가져와, 장마다 어울리는 후보를 추천하고 템플릿에 넣어 9장 이미지를 만들어요. 내려받기는 없어지고, 나는 후보 중에서 고르기만 해요.
7. **발행:** UTM 링크가 붙은 초안을 내가 확인하고 직접 올려요.
8. **성과 자동 불러오기:** 주간 수집 결과가 콘텐츠 원장에 자동으로 들어가고, 대시보드가 원장과 GA4를 읽어 채널별 저장 · 공유 · 방문을 보여 줘요.
9. **다음 전략 제안:** 반응률을 바탕으로 다음 글감 · 후킹 문구 · 소재를 근거 게시물과 함께 제안해요. 표본이 적으면 단정하지 않고 「더 지켜보기」로 표시해요.

## 5. 사람이 확인할 곳
- **글감:** 어떤 주제로 쓸지 내가 골라요.
- **겹침:** 플랫폼과 카페 내용이 너무 겹치지 않는지 봐요. 양쪽 노출에 영향이 있을 수 있어요.
- **사실:** 재료표의 「확인 필요」 값을 플랫폼과 맞춰요. 가격 · 혜택 조건이 틀리면 업체 신뢰에 바로 영향이 있어요.
- **표지 문구:** 3안 중 내가 골라요.
- **원고 · 톤:** 캐러셀 원고와 스레드 글이 광고처럼 보이지 않는지 내가 고쳐요.
- **사진:** 추천 후보 중 내가 고르고, 사용해도 되는 사진인지 확인해요.
- **전략:** 제안받은 다음 글감 · 문구 · 소재 중 무엇을 할지는 내가 정해요.
- **발행:** 자동으로 올리지 않아요. 마지막 버튼은 내가 눌러요.

## 7. 단계별 자동화 설계안

| 단계 | 입력 | 하는 일 | 출력 | 도구 · 연결 | 대시보드 탭 이름 |
|---|---|---|---|---|---|
| 1 | 품목 (장소 · 돌상 · 스냅) · 기간 | 검색 · 카페 · 스레드 · AI 답변 신호를 주제로 묶고 이미 쓴 글과 대조 | 글감 후보표 (근거 포함) | 주간 수집 결과 · 글감 노트 · 사이트맵 · 콘텐츠 원장 · Claude Code | 글감 찾기 |
| 2 | 가이드 글 주소 또는 카페 글 본문 | 숫자 · 조건을 업체 대장과 대조하고 채널별로 바꾸기 | 재료표 · 표지 문구 3안 · 캐러셀 원고 · 캡션 · 스레드 글 (UTM 링크 포함) | 공개 웹페이지 · 업체 대장 · 후킹 문구 모음 · UTM 규칙 · Claude Code | 채널 변환 |
| 3 | 확정한 원고 · 글에 나온 업체 | 공개 데이터에서 사진을 자동으로 가져와 장마다 후보를 추천하고 템플릿에 넣기 | 사진 후보 · 9장 이미지 | 공개 업체 데이터 · 사진 판단 Claude · 템플릿을 옮긴 HTML → PNG · 막히면 캔바에 붙일 문구와 사진 묶음 | 이미지 만들기 |
| 4 | 기간 | 콘텐츠 원장 · GA4 성과를 자동으로 읽고 다음 전략 제안 | 채널별 성과표 · 다음 글감 · 후킹 문구 · 소재 제안 | 주간 수집 루틴 · 콘텐츠 원장 · GA4 · Claude Code | 성과 · 다음 전략 |

가이드 글 쓰기는 이미 만든 워크플로우를 그대로 써서 탭에서 뺐어요. 1번 탭에서 고른 글감을 그쪽으로 넘기고, 완성된 글을 2번 탭에 넣어요. 4번 탭의 전략 제안은 1번 탭의 글감 후보로 다시 들어가요. 성과 데이터는 기존 콘텐츠 원장 하나만 쓰고 따로 쌓지 않아요.

**11/11에 완성할 첫 번째 탭:**
- 탭 이름: 채널 변환
- 11/11에 실제로 되어야 하는 것: 가이드 글 주소를 넣거나 카페 글 본문을 붙여 넣고 실행하면, 코드가 글을 읽어 재료표 · 표지 문구 3안 · 캐러셀 9장 원고 · 스레드 글을 만들어 보여 줘요. 값마다 출처와 대조 결과가 보이고, 대장에 없는 값은 「확인 필요」로 표시해요. 주소가 틀렸거나 본문을 못 읽으면 화면에 이유를 보여 줘요.

## 8. 3주 범위와 완성 기준
- 11/18까지 갈 곳: 「글감 찾기」로 이번 주 글감 후보표가 나오고, 「이미지 만들기」로 사진 자동 수집 · 후보 추천 · 9장 초안까지 나와요.
- 11/25에 "완성"이라고 말할 수 있는 상태: 네 탭을 이어서 두 바퀴 돌려요. 후보표에서 글감을 골라 가이드 글이나 카페 기존 글을 캐러셀과 스레드 글로 발행하고, 대시보드에서 성과를 자동으로 보고, 다음 글감 · 후킹 문구 · 소재 제안을 받아요. 글을 넣고 검수할 만한 채널별 초안이 나오기까지 1시간 안에 끝나요. 캐러셀 1개 전체 시간(지금 3시간쯤)의 Before → After도 재요.
- 이번에는 안 할 것: 인스타 · 스레드 자동 발행 · 카페 새 글 자동 작성 · 카페 글을 플랫폼으로 그대로 옮기기 · 릴스 · 광고 성과 분석. 카페 글은 「플랫폼용으로 새로 쓰기」 글감으로 제안받아 가이드 글 워크플로우로 새로 써요. 광고 성과 분석은 네 탭이 돈 뒤 다음 순서로 해요.

## 9. 팀과 겹칠 것, 도움받고 싶은 것
- 겹칠 것: 아람(블로그 → 캐러셀 · 릴스), 지지(글 → 카드뉴스 · 티스토리)와 「원문 → 재료 뽑기 → 채널별 초안 → 검수」 구조가 같아요. 채널별 변환 규칙 양식과 톤 유지 기준을 같이 만들면 좋겠어요.
- 내가 나눌 수 있는 것: 값마다 출처 · 확인일을 붙이는 재료표 양식, 캐러셀 장 구성, 표지 문구 기준, 검색 · 카페 · 스레드 신호를 글감으로 묶는 방법
- 도움받고 싶은 것
  - E팀의 카드뉴스 만들기에서 이미지 제작 부분을 가져다 쓸 수 있을까요?
  - 내가 답글 단 글 말고 스레드 키워드 검색 결과까지 안정적으로 모아 본 분이 있나요?
  - 주간 수집 결과를 구글 시트에 자동으로 넣어 본 분이 있나요? (Aside 예약 루틴 3개를 다 쓰고 있어요)
  - 11/4 팀 모임에서 A · B팀의 광고 성과 코드를 나중에 가져다 쓸 수 있는지 묻고 싶어요.
  - API 키 없이 Claude Code 구독만으로 대시보드 버튼에서 실행하는 방법을 해 보신 분이 있나요?
  - 사진 여러 장 중 글 내용에 어울리는 사진을 자동으로 고르게 해 보신 분이 있나요?
  - 같은 내용을 카페와 플랫폼에 나눠 올릴 때 노출에 문제없는 기준을 아시는 분이 있나요?

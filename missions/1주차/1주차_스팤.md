# 1주차 · PRD + 단계별 자동화 설계안 | 스팤 (F팀)

마감: **11/4(수) 저녁 9시** · 1차 싱크 전

## 1. 한 줄 요약
임원 지시가 담긴 **Plaud 녹취록**과 **작년 같은 공지**를 받아서 → **임원 보고용 개조식 메일**(예상 직원 반응 · 리스크 포함)과, 승인 후 **전 직원용 메일 · 게시판 공지**를 만들어 → 임원과 전 직원에게 보내기 직전까지 준비해 주는 자동화예요.

> 인사 · 총무 · 사내 커뮤니케이션을 맡고 있어요. 사내 공지 · 제도 안내는 같은 내용을 **임원 보고용**과 **직원 안내용**으로 두 번 써야 하고, 임원 보고가 한 번에 통과되지 않아 다시 쓰는 일이 많아요.

## 2. 지금 하는 방식
- 순서: 임원 지시 · 회의(Plaud 녹음) → 녹취록과 작년 같은 공지를 찾아 보며 정리 → **임원 보고 메일(개조식) 작성** → 임원이 "직원들 반응은? 리스크는?"을 물으면 보완해서 재보고 → 승인 → 같은 내용을 **직원용으로 톤 · 길이를 바꿔 다시 작성** → 사내 메일 · 그룹웨어 게시판에 올리기
- 주기와 걸리는 시간: 불규칙하고 **시즌(연말 · 연초 등)에 몰려요.** 한 건에 제가 쓰는 시간만 **1~2시간**(승인 대기 제외)
- 아쉬운 점
  - 대상마다 톤 · 길이를 처음부터 다시 써요.
  - 임원 보고가 주로 **직원 반응 · 리스크** 때문에 되돌아와요. 처음부터 담으면 재보고를 줄일 수 있어요.
  - 작년 공지가 게시판과 PC 폴더에 흩어져 있어 찾는 데도 시간이 들어요.

## 3. 필요한 데이터
| 데이터 | 어디서 | 권한 |
|---|---|---|
| 임원 지시 · 회의 녹취록 | Plaud (Claude 연결 → 녹취록 가져오기) | 있음 |
| 작년 같은 공지 · 지난 보고 메일 | 그룹웨어 게시판 · 내 PC 폴더(한글 · 워드) → 제가 골라서 `private/`에 텍스트로 넣기 | 있음 |
| 임원 수정 내용 · 이유 | 승인 메일 · 제 메모 → 반영 기록 파일 | 있음 |
| 회사 데이터를 AI 도구에 넣어도 되는지 | 사내 보안 · 정보보호 기준 | **확인 필요** |

- 실제 녹취록 · 공지 · 임직원 정보는 내 컴퓨터 `private/`에만 두고, 레포에는 **가짜 샘플**(가상의 회사 · 가상의 공지)만 올려요.

## 4. 자동화 흐름
1. **지시 정리:** Plaud 녹취록을 가져와 공지 재료 카드로 정리해요 — 무엇을 · 누구에게 · 언제부터/까지 · 숫자(비용 · 인원 · 날짜) · 임원이 강조한 말 · **아직 안 정해진 것**.
2. **임원 보고:** 재료 카드 + 작년 같은 공지 + 반영 기록을 보고 개조식 보고 메일 초안을 만들어요.
   - 맨 위에 결론과 결정이 필요한 사항
   - **예상 직원 반응 · 자주 나올 질문 · 리스크와 대응**을 처음부터 넣어요. (반려 이유 1순위)
   - 작년과 달라진 점을 따로 표시해요.
   - 녹취록에 없는 숫자 · 날짜는 지어내지 않고 「확인 필요」로 남겨요.
3. 제가 보고 고친 뒤 임원에게 보내요. **(발송은 제가 직접)**
4. **직원 공지:** 승인된 보고 내용을 전 직원용으로 바꿔요 — 메일용(짧게, 무엇을 · 언제까지 · 어떻게)과 게시판용(자세히, FAQ 포함) 두 가지.
   - 날짜 · 숫자 · 대상이 승인본과 같은지 자동으로 대조하고, 다르거나 빠진 곳을 표시해요.
5. **반영 기록:** 임원이 고친 내용과 이유를 한 줄씩 남기면, 다음 보고 초안을 만들 때 규칙으로 씁니다. (예: "비용은 항상 작년 대비로", "직원 불만 예상 시 대안 같이")

## 5. 사람이 확인할 곳
- **재료 카드:** 녹취록 해석이 맞는지, 「아직 안 정해진 것」이 맞는지 제가 확인해요.
- **임원 보고 발송 전:** 숫자 · 날짜 · 리스크 표현은 제가 최종 확인하고 직접 보내요.
- **직원 공지 게시 전:** 대조 결과에 「다름 · 빠짐」이 하나라도 있으면 고친 뒤에 올려요. 게시도 제가 직접 해요.
- **반영 기록:** 임원 피드백을 규칙으로 바꿀지는 제가 정해요. (한 번 나온 말은 메모로만, 두 번 이상 나오면 규칙으로)

## 6. 받고 싶은 결과물
내 컴퓨터에서 여는 대시보드(로컬 HTML) 하나에 탭 4개예요. 맨 위에는 「지금 진행 중인 공지와 다음 할 일」.

| 탭 | 보이는 것 |
|---|---|
| 지시 정리 | 녹취록 → 재료 카드(무엇 · 대상 · 일정 · 숫자 · 강조한 말 · 미정 사항), 원문 근거 위치 |
| 임원 보고 | 개조식 보고 메일 초안 · 예상 직원 반응 · 자주 나올 질문 · 리스크와 대응 · 작년 대비 달라진 점 · 「확인 필요」 목록, 복사 버튼 |
| 직원 공지 | 메일용 · 게시판용 공지 초안, 승인본과의 날짜 · 숫자 · 대상 대조표(같음 / 다름 / 빠짐) |
| 반영 기록 | 공지별 임원 수정 내용 · 이유, 규칙으로 승격된 목록, 공지별 걸린 시간 · 재보고 횟수 |

## 7. 단계별 자동화 설계안

| 단계 | 입력 | 하는 일 | 출력 | 도구 · 연결 | 대시보드 탭 이름 |
|---|---|---|---|---|---|
| 1 | Plaud 녹취록 | 공지 재료 뽑기 (무엇 · 대상 · 일정 · 숫자 · 미정 사항) | 재료 카드 | Plaud 연결 · Claude Code | 지시 정리 |
| 2 | 재료 카드 + 작년 공지 + 반영 규칙 | 개조식 보고 메일, 예상 직원 반응 · 리스크 · 작년 대비 변경점 | 임원 보고 초안 | Claude Code (대상별 톤 바꾸기 스킬) | 임원 보고 |
| 3 | 승인된 보고 내용 | 직원용 메일 · 게시판 공지로 바꾸고 날짜 · 숫자 · 대상 대조 | 공지 초안 2종 + 대조표 | Claude Code · 대조 스크립트 | 직원 공지 |
| 4 | 임원 수정 내용 · 이유 | 수정 기록 쌓기, 반복된 피드백을 규칙으로 정리, 시간 · 재보고 횟수 기록 | 반영 규칙 목록 | Claude Code · 로컬 파일 | 반영 기록 |

**11/11에 완성할 첫 번째 탭:**
- 탭 이름: 임원 보고
- 11/11에 실제로 되어야 하는 것: 녹취록(또는 재료 메모)과 작년 공지 파일을 `private/`에 넣고 명령 한 번 돌리면, 개조식 보고 메일 초안과 **예상 직원 반응 · 리스크와 대응 · 작년 대비 변경점 · 확인 필요 목록**이 탭에 떠요. 이번 연말 행사 · 휴무 · 조직 변경 안내 1건으로 실제로 돌려 봐요. (레포에는 가짜 샘플로 돌린 화면만)
- 왜 이 탭부터: 시간이 가장 오래 걸리고 재보고가 생기는 곳이에요. 임원이 묻는 직원 반응 · 리스크를 미리 담는 것만으로도 재보고를 줄일 수 있어요.

  - 혼자 다시 돌릴 수 있고, 반영 기록 탭에 공지별 걸린 시간 · 재보고 횟수가 남아 있어요.

- 11/4 팀 모임에서 정하고 싶은 것: F팀 공통 칸 이름 5~8개 (예: 원본 · 대상 · 채널 · 목적 · 꼭 들어갈 정보 · 금지 표현), 원본과 바꾼 글 대조 검수를 공용으로 같이 만들지
- 도움받고 싶은 것: 사내 자료를 AI에 넣을 때 다른 분들은 보안 기준을 어떻게 확인했는지, 가짜 샘플 공지를 어떻게 만들면 실제와 비슷하게 테스트할 수 있는지

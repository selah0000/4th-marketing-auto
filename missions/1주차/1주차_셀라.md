# 1주차 · PRD + 단계별 자동화 설계안 | 셀라 (G팀)

마감: **11/4(수) 오후 8시 29분** · 1차 싱크 전 (1주차 공통 안내 기준)

> 인터뷰 답변을 반영한 기획 초안. 자동 수집 방법과 세부 일정은 구현 전 검증이 필요하다.

## 1. 한 줄 요약
학원 원장님 대상 B2B 사업의 채널별 마케팅 지표와 신청·상담·결제 내역을 매일 자동으로 모아 팀이 성과와 처리할 일을 확인하고, 오픈채팅방의 고객 질문으로 콘텐츠 제목과 기획안을 만드는 공유 대시보드.

- 대상 채널: 인스타그램 광고, 네이버 블로그, 네이버 카페. 오픈채팅방은 고객 질문·콘텐츠 기획 용도로 별도 관리한다.
- 서비스: 블로그 마케팅, AI 강의, 학원 운영관리 시스템, 네이버 플레이스 관련 서비스 등. 서비스는 수시로 달라지므로 고정 목록으로 제한하지 않는다.
- 전체 B2B 합계와 서비스별 성과를 모두 조회한다.
- 초대한 팀원만 접속하며, 모두 같은 상세 내역을 조회한다.

## 2. 지금 하는 방식
- 각 채널 관리자 화면에 따로 접속해 성과를 확인한다.
- 구글 신청서 응답 시트에서 신청 내역과 상담 진행 상태를 관리한다.
- 자체 사이트 카드결제, 사이트 오류 시 이용하는 네이버 스마트스토어, 계좌이체 내역을 각각 확인한다.
- 계좌이체는 결제 담당자 셀라가 확인한 뒤 팀 슬랙에 공유한다.
- 신청·결제 시 고객에게 유입 경로를 물어본다.
- 주기와 걸리는 시간: 매일 약 30분. 시간 단축보다 자동 수집과 누락 확인이 우선이다.

## 3. 필요한 데이터
| 출처 | 필요한 정보 | 권한·연결 상태 |
|---|---|---|
| 인스타그램 광고 관리자 | 일별 광고비, 노출·조회 등 성과 | 대부분 관리자 권한 보유. 자동 연결 권한·방법 확인 필요 |
| 네이버 블로그·카페 | 콘텐츠 발행일·발행 수, 조회수, 체류시간 | 별도 광고비 없음. 지표 제공 여부와 자동 수집 방법 확인 필요 |
| 구글 신청서 응답 시트 | 신청일, 이름, 유입 경로, 서비스, 상담 진행 상태 | 관리자 접근 범위와 자동 연동 권한 확인 필요 |
| 자체 사이트 결제 장부·네이버 스마트스토어 | 결제일, 상품명, 금액, 이름, 결제 상태, 가능한 주문 식별정보 | 경로별 데이터 제공·추출 방법 확인 필요 |
| 계좌이체 확인 기록·팀 슬랙 | 확인된 입금일, 입금자명, 금액, 서비스 등 | 실제 기록 형식 및 자동 연결 가능 여부 확인 필요 |
| 직접 운영하거나 참여 중인 오픈채팅방 | 고객 질문·고민, 주제별 반복 빈도, 분석 대상 기간 | 방별 접근·활용 조건과 대화 자동 수집 가능 여부 확인 필요 |

- 대부분 셀라가 관리자 권한을 보유하지만, 관리자 화면 접근이 자동 연동 가능성을 보장하지는 않는다.
- 서비스명·상품명·신청서로 서비스를 구분할 수 있다. 같은 서비스의 다른 이름은 공통 분류에 연결하고 새 서비스도 추가할 수 있게 한다.
- 신청·상담과 결제의 공통 정보는 이름 또는 입금자명 정도다. 자동 확정에 충분한 공통 식별번호는 현재 없다.
- 실데이터·고객정보·인증정보는 공개 과제 저장소에 넣지 않는다. 과제 예시는 가상 데이터로 만든다.

## 4. 자동화 흐름
1. 채널별 수집 가능 지표, 권한, 데이터 제공 방식부터 검증한다.
2. 매일 오전 9시(한국 시간)까지 전날 실적을 자동 수집하는 것을 목표로 한다. 수동 입력·파일 업로드를 기본 운영 방식으로 두지 않는다.
3. 날짜, 채널, 서비스, 결제 경로를 정리하고 중복 기록을 확인한다. 유입 채널과 결제 경로는 별도로 관리한다.
4. 고객이 답한 유입 경로를 기준으로 신청·결제를 채널별로 집계한다. 답변이 없거나 불분명하면 ‘유입 미확인’으로 남긴다.
5. 신청·상담과 결제는 이름·입금자명으로 연결 후보를 만들고 셀라가 확인해 확정한다. 이름만 같다는 이유로 자동 확정하지 않는다. 신청 없이 직접 결제한 경우도 별도 반영한다.
6. 전체 및 서비스별 성과, 미진행 상담, 미확인 결제를 보여준다.
7. 활용 가능한 오픈채팅방 자료에서 개인 식별정보를 제외하고 질문·고민을 주제별로 정리한 뒤 블로그·카페·인스타그램 제목과 기획안을 제안한다.
8. 수집 실패·연결 끊김·자료 누락은 대시보드에 표시하고 팀 슬랙에 알린다. 실제 알림 대상 채널은 구현 시 지정한다.

### 집계 기준 초안
- 신청, 실제 상담 진행, 결제를 구분한다. 신청서 제출을 상담 완료로 세지 않는다.
- 일별 신청·상담·결제 건수는 각 발생일 기준으로 표시한다. 상담일 기록 유무는 확인이 필요하다.
- 같은 날 발생한 신청과 결제가 반드시 같은 고객의 전환은 아니다. 개인 연결이 확인된 전환과 단순 일별 건수를 구분한다.
- 광고비 대비 성과는 인스타그램 유료 광고에 적용한다. 신청당 비용·결제당 비용·광고비 대비 매출은 비용과 귀속 기준이 확인된 범위에서 계산한다.
- 블로그·카페는 발행·조회·체류 지표와 신청·상담·결제를 확인한다. 체류시간이 제공되지 않으면 ‘수집 불가’로 표시한다.
- 수집 실패·연결 준비 중·제공되지 않는 지표를 실제 0건과 구분한다. 채널별 마지막 수집 시각과 데이터 기준일을 표시한다.
- 취소·환불 반영 방식과 매출 기준, 중복 결제 구분 규칙은 구현 전 확정한다.

## 5. 사람이 확인할 곳
- 셀라: 신청·상담과 결제의 연결 후보, 동명이인·대리 입금 등 예외 확인.
- 담당 팀원: 미진행 상담·미확인 결제 처리, 신규 서비스 분류와 유입 경로 미확인 건 검토.
- 콘텐츠 담당자: 생성된 제목·기획안의 적합성과 사실관계 검토 후 발행 소재 선택.
- 초기 연결 시: 관리자 권한, 자동 수집 범위, 외부 오픈채팅방 자료 활용 조건 확인.
- 수집 오류 발생 시: 알림을 확인하고 연결 복구. 미수집 구간이 보완됐는지 확인.

## 6. 받고 싶은 결과물
- 날짜·채널·서비스로 조회할 수 있는 팀 공유 대시보드.
- 전체 채널 요약: 광고비, 노출·조회, 콘텐츠 발행 수, 제공되는 체류 지표, 신청·상담·결제 건수, 매출과 계산 가능한 비용 대비 성과.
- 처리할 일: 미진행 상담, 결제 연결 후보, 유입·서비스 미확인 내역.
- 고객 질문·콘텐츠 아이디어: 분석 기간, 주제, 반복 빈도, 고객 고민 요약, 블로그·카페·인스타그램 제목과 기획안.
- 수집 상태: 마지막 갱신 시각, 미연결·실패·누락 항목 및 팀 슬랙 오류 알림.
- 초대된 팀원만 동일한 상세 화면에 접근한다.

## 7. 단계별 자동화 설계안
| 단계 | 입력 | 하는 일 | 출력 | 도구 · 연결 | 대시보드 탭 이름 |
|---|---|---|---|---|---|
| 1 | 채널별 일별 성과, 신청·상담·결제 집계 | 자동 수집·정규화, 채널·서비스별 요약 및 수집 상태 표시 | 일별 전체 성과와 누락 현황 | 채널별 연결 방법 검증, 구글 시트, 예약 실행, 슬랙 | 전체 채널 요약 |

| 3 | 세 경로의 결제와 신청·상담 기록 | 중복 확인, 이름 기반 후보 제시, 사람의 확정 반영 | 결제·매출·연결 미확인 내역 | 자체 사이트·스마트스토어·입금 확인 기록 연결 검토 | 결제·전환 |
| 4 | 활용 가능한 오픈채팅방 질문·고민 | 개인 식별정보 제외, 주제 분류, 제목·기획안 생성 | 주제별 질문과 채널별 콘텐츠 기획안 | 대화 수집 방식 검증, AI 분류·기획 | 고객 질문·콘텐츠 아이디어 |

**11/11에 완성할 첫 번째 탭:**
- 탭 이름: 전체 채널 요약.
- 실제로 되어야 하는 것: 자동 연결을 검증한 데이터가 한 개 이상 실제로 갱신되고, 일별 성과를 화면에서 조회할 수 있다.
- 자동 연결이 확인된 지표부터 표시한다. 나머지는 ‘연결 준비 중’으로 구분하고 실제 0과 혼동하지 않는다.
- 마지막 갱신 시각과 수집 상태를 확인할 수 있다. 팀 공유를 위한 접근 방식도 검증한다.

## 8. 3주 범위와 완성 기준
아래 일정은 목표 초안이며, 연결 검증 결과에 따라 실현 가능성을 판단한다. 미연결 상태를 완전 자동화 완료로 보지 않는다.

- **11/18까지 갈 곳:** 인스타그램·블로그·카페의 수집 가능 지표와 신청·상담을 연결하고, 결제 데이터 통합 및 사람의 연결 확정 흐름을 구현한다. 오픈채팅방 수집·활용 가능성을 검증하고 콘텐츠 기획 탭을 시험한다.
- **11/25에 완성이라고 말할 수 있는 상태:**
  - 범위 내 수집 가능 지표가 수동 입력 없이 매일 오전 9시까지 갱신된다. 원천 자료 지연은 별도로 표시한다.
  - 전체 및 변경 가능한 서비스별 성과를 조회한다.
  - 신청·상담·결제와 처리할 일을 구분하고, 결제 연결 확정 기능이 동작한다.
  - 초대한 팀원만 접속해 같은 상세 내역을 볼 수 있다.
  - 수집 실패·누락을 실적 0과 구분하고 대시보드·팀 슬랙으로 알린다.
  - 활용 가능한 오픈채팅방 자료로 주제별 정리와 세 채널의 제목·기획안을 생성한다.
  - 원천 기록과 대시보드 집계가 맞는지 표본을 대조하고, 수집 오류 및 접근 제한 동작을 확인한다.
- **이번에는 안 할 것:** 카카오비즈니스 채널 연동, 콘텐츠 자동 발행, 광고 자동 집행·예산 변경, 공통 식별번호를 위한 사이트 개편, 이름만으로 고객·결제 자동 확정.
- **미확정 사항:** 채널별 자동 수집 방법, 계좌이체 기록의 수집원·형식, 오픈채팅방 자동 수집, 상담일 기록, 취소·환불 및 매출 기준, 실제 배포·인증 도구. 자동 수집이 불가능한 항목은 이유와 영향 범위를 명시하고 범위를 다시 협의한다.

## 9. 팀과 겹칠 것, 도움받고 싶은 것
- G팀의 ‘광고 → 문의·상담 연결’과 신청·상담·결제 전환 관리가 겹친다.
- 채널별 자동 수집 가능 여부, 필요한 권한, 데이터 연결 방법을 도움받고 싶다.
- 광고 → 신청·상담·결제 연결 방식과 채널 귀속, 중복·미확인 처리, 날짜·전환율 집계 기준을 함께 정하고 싶다.
- 공통 데이터 형식과 가상 샘플, 정규화·집계 코드는 공유하고 각자의 실제 데이터 연결은 개별 관리한다.

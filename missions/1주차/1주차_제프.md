# 1주차 · PRD + 단계별 자동화 설계안 | 제프 (A팀)

마감: **11/4(수) 저녁 9시** · 1차 싱크 전

## 1. 한 줄 요약
지금까지 X · 인스타 같은 우리 계정만으로 고객을 모아 온 Shopify 직영몰에 **Meta 광고를 처음 시작하면서**, 광고 전 유입 · 매출을 기준선으로 잡고 → 광고를 켠 뒤 「광고가 기준선 위에 매출을 얼마나 더했는지」와 이번 주 「늘리기 · 유지 · 끄기 · 보류」 제안(근거 숫자 포함)을 만들어 매주 월요일 나(몰 운영 책임자)에게 주는 대시보드예요.

> 일본에서 캐릭터 굿즈 직영몰(Shopify)을 운영하고 있어요. 그로스 담당이 따로 없어서 광고 · 매출 판단을 제가 직접 해요. 유료 광고(Meta · 디스플레이 · 구글 DA)는 한 번도 안 해 봤고, 11/10 전후로 Meta 광고를 처음 켜요. 블랙프라이데이(11/27) → 연말연시 성수기 전에 광고를 굴리면서 판단하는 틀을 만드는 게 목표예요.

## 2. 지금 하는 방식
- 순서: X · 인스타에 신상품 · 이벤트 게시 → 몰 매출은 Shopify 관리 화면에서 가끔 확인 → 어느 게시물 · 채널에서 손님이 왔는지는 거의 안 봐요
- 주기와 걸리는 시간: 정해진 주기 없이 생각날 때 가끔 봐요. 채널별로 나눠 보는 방법이 없어서, 솔직히 지금은 제대로 못 보고 있어요. 그래서 이번 목표는 시간을 줄이는 것보다 **매주 월요일에 빠짐없이 보고 판단까지 하는 것**이에요.
- 아쉬운 점: 광고를 처음 켜는데, 광고 전 숫자를 모르면 광고가 매출을 늘렸는지 원래 나던 매출인지 구분할 수 없어요. 광고 숫자를 보고 다음 행동을 정하는 기준도 아직 없어요.

## 3. 필요한 데이터
| 데이터 | 어디서 | 권한 |
|---|---|---|
| 주문 (날짜 · 금액 · 상품 · 수량 · 신규/재구매 · 유입 경로 · UTM) | Shopify 관리 화면 주문 내보내기(CSV) · 유입 경로 보고서 → 나중엔 Shopify Admin API | 있음 |
| Meta 광고 성과 (캠페인 · 광고 세트 · 광고비 · 노출 · 클릭 · 구매 · 구매 금액) | 광고관리자 내보내기(일 단위 CSV) → 나중엔 Marketing API | 있음 (11/10 광고 시작 후 데이터 생김) |
| Meta 픽셀 · 구매 이벤트 연결 상태 | Shopify의 Facebook & Instagram 앱 · 이벤트 관리자 | 있음 · **연결 여부 확인 필요** |
| 목표 숫자 (ROAS · CPA) · 시즌 일정 | 내가 정해서 `goal.md`에 저장 | 있음 |

- 실제 데이터는 내 컴퓨터 `private/`에만 두고, 레포에는 가짜 샘플 데이터만 올려요.

## 4. 자동화 흐름
**광고 켜기 전 (지금 ~ 11/10)**
1. Shopify 주문 CSV를 `private/`에 넣으면, 최근 4주를 유입 경로(X · 인스타 · 검색 · 직접 · 기타)별 주문 · 매출 · 객단가로 나눠 **기준선**을 만들어요.
2. 광고를 켜기 전에 준비가 됐는지 점검해요: 픽셀 구매 이벤트가 잡히는지, X · 인스타 링크에도 UTM이 붙어 있는지(광고와 섞이지 않게), 목표 ROAS · CPA가 정해졌는지.

**광고 켠 뒤 (11/10 ~)**
3. 매주 월요일 Meta 광고 CSV와 Shopify 주문 CSV를 넣으면, A팀 공통 칸(날짜 · 채널 · 캠페인 · 광고비 · 주문 수 · 매출 등)으로 합쳐요.
4. Meta가 잡은 구매 금액과 Shopify 실제 매출(UTM이 Meta인 주문)을 나란히 놓고 차이를 보여 줘요.
5. 스크립트가 늘 같은 방식으로 계산해요: 매출 · 주문 수 · 객단가 · ROAS · CPA · 신규/재구매. 그리고 **기준선 대비** 이번 주 전체 매출이 얼마나 늘었는지(광고 외 채널 매출이 줄지 않았는지도) 봐요.
6. 정해 둔 규칙으로 캠페인 · 광고 세트별 「늘리기 · 유지 · 끄기 · 보류」와 근거 숫자 · 규칙 번호를 뽑아요.
   - 판단은 늘 **목표 ROAS와 같이** 봐요. 매출이 늘어도 ROAS가 목표 아래면 늘리지 않아요. 목표가 없으면 「높다 · 낮다」를 말하지 않아요.
   - 처음 1~2주는 Meta가 학습하는 기간이라, 집행 기간이 짧거나 쓴 광고비 · 구매 수가 적으면 「보류(아직 판단하기 일러요)」로 표시해요.
   - 규칙은 ROY 키트의 판단 규칙을 출발점으로, 처음 광고하는 굿즈 몰에 맞게 고쳐서 써요.
7. 「이번 주 할 일 3개」와 한국어 · 일본어 리포트 1장을 만들어요. 확인 못 한 숫자는 지어내지 않고 「확인 못 함」으로 남겨요.
8. 내가 보고 승인 / 보류 / 반대를 찍고 **이유를 한 줄** 남겨요. 승인한 것만 광고관리자에서 직접 반영하고, 쌓인 이유는 판단 규칙에 다시 반영해요.

## 5. 사람이 확인할 곳
- **광고 시작 전:** 픽셀 · 구매 이벤트 연결과 목표 ROAS · CPA, 첫 예산은 내가 정하고 확인해요. 테스트 주문으로 구매가 실제로 잡히는지 한 번 봐요.
- **판단 제안:** 늘리기 · 유지 · 끄기는 승인 / 보류 / 반대를 내가 해요. 이유를 한 줄 남기고, 같은 이유가 반복되면 규칙으로 옮겨요. 자동화가 광고 계정을 직접 바꾸지 않아요.
- **두 데이터가 안 맞을 때:** Meta가 잡은 구매 금액과 Shopify 실제 매출이 크게 다르면 「확인 필요」로 표시하고 내가 봐요. 이때는 판단도 보류해요.
- **내가 직접 끈 광고:** 광고관리자에서 끈 캠페인은 끈 이유를 기록해 두고, 다음 판단 규칙에 반영해요.

## 6. 받고 싶은 결과물
내 컴퓨터에서 여는 대시보드(로컬 HTML) 하나에 탭 4개예요. 맨 위에는 「이번 주 할 일 3개」.

| 탭 | 보이는 것 |
|---|---|
| 기준선 | 광고 전 4주 유입 경로별 주문 · 매출 · 객단가 · 신규/재구매, UTM 없는 주문 비율 경고 |
| 광고 준비 | 픽셀 구매 이벤트 · UTM 규칙 · 목표 숫자 점검표 (된 것 / 안 된 것) |
| 광고 성과 | Meta CSV + Shopify 합본, Meta 구매 금액 vs 실제 매출 차이, ROAS · CPA, 기준선 대비 전체 매출 변화 |
| 이번 주 판단 | 캠페인별 늘리기 · 유지 · 끄기 · 보류, 근거 숫자 · 규칙 번호 · 목표 대비, 승인 · 보류 · 반대 + 이유 한 줄, 한 · 일 리포트 |

## 7. 단계별 자동화 설계안

| 단계 | 입력 | 하는 일 | 출력 | 도구 · 연결 | 대시보드 탭 이름 |
|---|---|---|---|---|---|
| 1 | Shopify 주문 CSV (광고 전 4주) | 유입 경로 · UTM별로 주문 · 매출 · 객단가 · 신규/재구매 나누기 | 기준선 표 | 파일 내보내기 · python 스크립트 | 기준선 |
| 2 | 몰 주소 · 이벤트 관리자 · `goal.md` | 픽셀 구매 이벤트 · UTM 규칙 · 목표 숫자가 준비됐는지 점검 | 준비 점검표 | Claude Code · Chrome | 광고 준비 |
| 3 | Meta 광고 CSV + Shopify 주문 CSV | A팀 공통 칸으로 합치고, Meta 구매 금액 vs 실제 매출 차이, ROAS · CPA, 기준선 대비 변화 계산 | 주간 광고 성과표 | python 스크립트 (계산은 AI가 아니라 스크립트) | 광고 성과 |
| 4 | 광고 성과표 + 목표 + 판단 규칙 | 늘리기 · 유지 · 끄기 · 보류와 근거, 할 일 3개, 승인 기록, 한 · 일 리포트 | 이번 주 판단표 + 리포트 | Claude Code · 로컬 대시보드 | 이번 주 판단 |

**11/11에 완성할 첫 번째 탭:**
- 탭 이름: 기준선
- 11/11에 실제로 되어야 하는 것: Shopify 주문 CSV를 `private/`에 넣고 명령 한 번 돌리면, 광고 전 4주가 유입 경로별(X · 인스타 · 검색 · 직접 · 기타) 주문 · 매출 · 객단가로 나뉘어 탭에 떠요. 유입 경로나 UTM이 비어 있는 주문이 많으면 화면에 경고가 떠요. (레포에는 가짜 샘플로 돌린 화면만)
- 왜 이 탭부터: 광고 데이터는 11/10 이후에야 생기지만 주문 데이터는 지금 있어요. 그리고 광고 전 숫자가 없으면 광고가 매출을 늘렸는지 판단할 수 없어서요.

## 8. 3주 범위와 완성 기준
- 11/18까지 갈 곳: 탭 1~3 (기준선 · 광고 준비 · 광고 성과). 광고 첫 주 실제 데이터로 한 번 돌려 보기
- 11/25에 "완성"이라고 말할 수 있는 상태: 월요일에 파일 2개 넣고 명령 한 번이면 4개 탭이 다 채워지고, 판단을 보고 바로 승인 / 보류할 수 있어요. 혼자 다시 돌릴 수 있고, 광고 2주치 승인 · 반대 이유로 판단 규칙을 한 번 이상 고친 기록이 있어요. 바로 다음 주 블랙프라이데이 기간엔 일 단위로 돌려 볼 거예요.
- 이번에는 안 할 것: 디스플레이 · 구글 DA 광고, 광고 자동 변경(예산 · 켜고 끄기), 광고 소재 자동 제작(첫 소재는 직접 만들고 C팀 · Copy OS 방식을 참고), 퍼널(유입 → 장바구니 → 결제) 병목 분석, API 자동 수집(파일로 먼저 돌리고 여유 있으면 3주차)

## 9. 팀과 겹칠 것, 도움받고 싶은 것
- 겹칠 것: A팀 공통 주제(Meta 성과를 매출과 함께 보기). 저는 **Shopify 주문 → 공통 칸 변환**을 맡아 `teams/A팀/`에 올릴게요. 초이의 성과표(ROAS 표) 스킬을 제 데이터로 써 보고 결과를 남길게요.
- 출발점: 에밀리의 ROY 스타터 키트를 제 작업 폴더에 복사해 이름을 바꿔 쓰고, 바꾸는 부분은 ① 광고 전 기준선과 비교 ② Shopify 실제 매출 연결 ③ 처음 광고하는 굿즈 몰에 맞춘 판단 규칙(학습 기간 보류 · 시즌 · 세트 구매) ④ 한 · 일 리포트예요.
- 11/4 팀 모임에서 정하고 싶은 것: A팀 공통 칸 이름 5~8개, 날짜 · 통화 형식, Meta 구매 금액과 실제 매출이 다를 때 어느 쪽을 기준으로 할지
- 도움받고 싶은 것:
  - Meta 광고를 처음 시작할 때 첫 캠페인 구조 · 예산 · 학습 기간을 어떻게 잡는지
  - Shopify에서 픽셀 · 전환 API(구매 이벤트)가 제대로 잡히는지 확인하는 법
  - 처음 광고할 때 「보류」에서 「판단」으로 넘어가는 기준(광고비 · 구매 수 · 기간)

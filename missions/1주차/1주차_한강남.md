# 1주차 · PRD + 단계별 자동화 설계안 | 한강남 (G팀)

마감: **11/4(수) 오후 8시 29분** · 1차 싱크 전

> 정수기·생활가전 렌탈 중개 회사를 운영합니다. 광고는 **네이버 GFA 하나**만 돌리고, 같은 GFA 계정으로 **레미와 짝**이 되어 조사 → 기획 → 운영 → 결과 → 다시 기획을 한 바퀴씩 함께 돕니다.
> 이 문서의 숫자는 전부 **샘플**입니다. 실제 광고비 · 매출 · 고객 정보는 올리지 않습니다.

## 1. 한 줄 요약
**네이버 GFA 성과**와 **우리 상담 · 계약 기록**을 날짜 · 소재 기준으로 붙여서, 소재 · 타깃마다 **"유지 / 고치기 / 끄기" 제안과 근거**를 매일 아침 한 장으로 만들어 대표(나)에게 준다. 내가 승인한 것만 운영에 반영하고, 1주 뒤 효과를 다시 잰다.

| 받는 것 | 만드는 것 | 주는 사람 |
|---|---|---|
| GFA 보고서(노출 · 클릭 · 비용) + 상담 시트(날짜 · 유입 채널 · 상태) | 소재별 상담 1건당 비용 · 계약 1건당 비용 · 막힌 곳 · 제안표 | 나(승인) → 운영 담당(반영) → 레미(같이 분석 · 소재 개선) |

## 2. 지금 하는 방식
- 순서:
  1. 상담 시트에서 GFA로 들어온 상담 건수를 본다
  2. 광고 화면(또는 대행사가 주는 보고)에서 비용 · 클릭을 본다
  3. 상담이 계약까지 갔는지는 상담 시트의 **'계약완료' 표시**와 **계약 시트**를 따로 봐야 안다
  4. 숫자를 머릿속으로 맞춰 보고 "이 소재가 좋은 것 같다"를 감으로 판단해 운영에 요청한다
- 주기와 걸리는 시간: **매일 아침 · 저녁 2번, 한 번에 약 10분** (하루 20분, 주 약 2시간 20분)
- 문제:
  - 광고 숫자와 상담 · 계약이 서로 다른 화면에 있어서, **어느 소재가 계약을 만드는지** 모른다
  - 클릭은 많은데 상담이 적은 건지(랜딩 문제), 클릭 자체가 비싼 건지(소재 · 타깃 문제) 가르지 못한다
  - 바꾼 뒤에 좋아졌는지 기록이 남지 않는다

| 데이터 | 어디서 | 권한 |
|---|---|---|

| 계약 여부 | 상담 탭의 '계약완료' 표시 + 계약 시트 | 있음 (어느 칸을 읽을지 11/11 전 확정) |

- GitHub에는 **가짜 샘플 파일**만 올린다. 실제 파일은 `private/`에 둔다.

## 4. 자동화 흐름
```
[매일 아침]
GFA 보고서 가져오기 ─┐
                       ├→ 날짜·소재로 붙이기 → 지표 계산 → 막힌 곳 판정 → 제안 + 근거
상담·계약 세 칸 읽기 ─┘                                                     │
                                                                            ▼
                                      [나 승인 ✅/❌] → 운영 반영 → 변경 기록
                                                                            │
[1주 뒤] 바꾸기 전 7일 vs 후 7일 비교 → 판단 규칙 고치기 → 다음 기획(레미와) ◀┘
```

**레미와 같이 도는 루프** (같은 GFA 계정)
| 단계 | 한강남 | 레미 |
|---|---|---|
| 조사 | 상담 · 계약이 붙은 성과표 | 경쟁사 소재 · 전환율 인사이트 |
| 기획 | 끌 것 / 키울 것 제안 | 새 소재 개선안 |
| 운영 | 승인 · 반영 | 반영 확인 |
| 결과 | 전후 비교(상담 · 계약) | 소재별 반응 비교 |
| 다시 기획 | 판단 규칙 수정 | 다음 소재 가설 |

**판단 규칙 (AI에게 주는 "해야 할 것 / 하지 말 것")**
1. 최종 판정은 **계약 1건당 비용**. 상담 1건당 비용은 중간 신호.
2. **상담 1건당 비용 = 클릭 1번 값(CPC) ÷ 클릭한 사람 중 상담 남긴 비율.**
   - CPC가 높다 → 소재 · 타깃 문제 → 소재 문구 · 이미지, 타깃부터 본다
   - 비율이 낮다 → 랜딩 문제 → 광고에서 본 제품 · 혜택이 랜딩 첫 화면에 그대로 있는지 본다
3. CTR이 떨어지면 같은 소재가 며칠째인지(피로) 먼저 확인한다.
4. **숫자를 만든 실제 소재와 랜딩을 열어서 같이 본다.** 그날 운영에서 바뀐 것(예산 · 소재 교체)을 함께 적는다.
5. 상담이 기준 건수보다 적으면 "판단 보류"라고 쓴다. 숫자를 지어내지 않는다.
6. 하지 말 것: 예산 · 입찰을 직접 바꾸기, 근거 없는 "최대 ○○원" 같은 문구 제안, 샘플 숫자를 실제처럼 쓰기, 고객 개인정보 읽기.
- 기준 숫자(목표 상담당 비용 · 보류 기준 건수 · 피로 일수)는 내가 정해 비공개 설정 파일에 둔다.

## 7. 단계별 자동화 설계안
| 단계 | 입력 | 하는 일 | 출력 | 도구 · 연결 | 대시보드 탭 이름 |
|---|---|---|---|---|---|
| 1 | GFA 보고서 엑셀(아무 모양) | 열 이름을 뜻으로 맞춰 읽고 일별 · 소재별로 정리 | 성과표 | Claude Code · Python (이미 만든 리포트 일꾼 재사용) | **성과 가져오기** |
| 2 | 성과표 + 상담 시트 세 칸(날짜 · 채널 · 상태) | 날짜 · 소재로 상담 · 계약을 붙임 | 상담 · 계약이 붙은 성과표 | 구글 시트 읽기 (CSV) | **상담 붙이기** |
| 3 | 붙은 성과표 | CTR · CPC · 상담당 · 계약당 계산, 막힌 곳(소재/랜딩) 판정 | 진단표 | Claude Code + 판단 규칙 | **막힌 곳** |
| 4 | 진단표 + 소재 이미지 · 랜딩 | 유지 / 고치기 / 끄기 제안과 근거 작성 | 제안표 · 아침 한 장 | Claude Code | **오늘 제안** |
| 5 | 제안표 | 내가 ✅/❌, 반영한 변경을 기록 | 승인 · 변경 기록 | 대시보드 버튼 → 시트 기록 | **승인 · 변경** |
| 6 | 변경 기록 + 이후 성과 | 바꾸기 전 7일 vs 후 7일 비교, 판단 규칙 수정안 | 효과표 · 규칙 수정안 | Claude Code | **전후 비교** |

**11/11에 완성할 첫 번째 탭:**
- 탭 이름: **상담 붙이기** (1 · 2단계)
- 11/11에 실제로 되어야 하는 것: 샘플 GFA 보고서와 샘플 상담 기록을 넣으면, 대시보드에 **소재별 상담 1건당 · 계약 1건당 비용 표**가 뜬다. 같은 코드가 내 컴퓨터에서는 실제 파일로도 돈다.

## 8. 3주 범위와 완성 기준
- 11/18까지 갈 곳: 1~4단계 탭이 샘플로 돌고, 실제 데이터로 **아침 한 장**이 매일 나온다. 레미와 같은 성과표를 본다.
- 11/25에 "완성"이라고 말할 수 있는 상태: 최소 1주 동안 아침 한 장이 매일 나오고, 내가 승인 · 거절한 기록이 남고, **승인한 변경 1건 이상의 전후 비교**가 6단계 탭에 보인다. 아침 · 저녁 확인이 하루 20분에서 10분 이하로 준다.
- 이번에는 안 할 것: 예산 · 입찰 자동 변경, 광고 계정 자동 로그인, 메타 · 당근 광고, 새 소재 이미지 자동 제작(레미의 소재 개선안과 연결만), 네이버 검색광고(지금 운영 안 함).

## 9. 팀과 겹칠 것, 도움받고 싶은 것
- **G팀 공통(광고 → 문의 · 상담 연결)**: 2단계 '상담 붙이기'가 팀 공통 부분입니다. 각자 시트 모양이 달라도 아래 칸으로 맞추면 같은 코드를 쓸 수 있어요. 11/4 조별 모임에서 정할 데이터 모양 제안:
  `날짜 · 매체 · 캠페인 · 소재 · 노출 · 클릭 · 비용 · 문의 · 계약`
- **레미와**: 같은 GFA 계정 · 같은 성과표. 레미의 소재 인사이트가 4단계 '고치기' 제안의 근거로 들어가고, 내 상담 · 계약 결과가 레미의 소재 판단 근거로 돌아가는 구조로 맞추고 싶어요.
- 도움받고 싶은 것: GFA 보고서를 API로 자동으로 받는 방법, 소재별 UTM으로 상담까지 추적하는 방법, 대시보드에 승인 버튼 붙이는 방법.
